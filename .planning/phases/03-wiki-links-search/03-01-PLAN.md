  <name>Task 01: Create FTS5 migration with external content table and triggers</name>
  <files>webui/migrations/002_fts5_search.sql</files>
  <action>
Create a new migration file that:

1. Creates FTS5 virtual table with external content pointing to notes table:
```sql
CREATE VIRTUAL TABLE IF NOT EXISTS notes_fts USING fts5(
    title,
    content,
    content='notes',
    content_rowid='id',
    tokenize='porter unicode61'
);
```

2. Creates AFTER triggers (NOT BEFORE - critical for FTS5 external content):
   - `notes_fts_insert` - AFTER INSERT on notes, insert into FTS
   - `notes_fts_delete` - AFTER DELETE on notes, delete from FTS using special syntax
   - `notes_fts_update` - AFTER UPDATE on notes, delete old + insert new

3. Rebuilds the FTS index from existing data (handles migration on existing databases):
```sql
INSERT INTO notes_fts(notes_fts) VALUES('rebuild');
```

**Critical details from research:**
- Use AFTER triggers, not BEFORE (BEFORE triggers fail because FTS5 needs to fetch old values)
- Delete syntax: `INSERT INTO notes_fts(notes_fts, rowid, title, content) VALUES('delete', old.id, old.title, old.content)`
- porter tokenizer enables stemming (search "run" matches "running")
- unicode61 handles international characters

The migration will auto-apply on next `tauri dev` via the existing migration runner in db/mod.rs.
